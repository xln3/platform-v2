# GEO 报价单生成服务

## 当前目标

运营人员在 `/platform/operations/quotations` 为任意品牌/客户选择套餐或自定义服务，逐项填写
单价和数量，由后端计算小计与总价并生成 DOCX。调用方通过 `artifact_kind` 明确选择“报价单表格”
“查询附件”或“完整报价单”；缺省为完整报价单。目标词 XLSX 是否必填、是否调用研究模型以及 DOCX
包含哪些章节，都由制品类型和已选服务共同决定。出具公司与固定商务条款仍由模板统一配置，
“任意客户”不表示任意出具主体或任意合同条款。

报价单生成器只确认服务范围、客户输入、交付物和价格状态。它不代表服务已经执行，也不把未经
采样的排名变化、拉踩归因或发帖效果写成事实。

## 五项原子服务

| 编号 | 简称       | 正式名称                 | 关键输入                                                             | 交付输出                                                     |
| ---- | ---------- | ------------------------ | -------------------------------------------------------------------- | ------------------------------------------------------------ |
| 1    | 测试       | AI 推荐排名效果测试      | 已有或我方推荐后由客户冻结的问题；竞品；开放 API 与豆包 App 采集配置 | 两渠道逐题证据；提及率、排名、Top1/3/5；观测差异             |
| 2    | 找拉踩帖   | 主动拉踩内容核查         | 己方帖子/稿件 URL；作者、委托或审批归属证据；事实材料；核查范围      | 疑似拉踩帖子、逐字证据、URL、截图、事实核查和整改建议        |
| 3    | 找被拉踩帖 | 被拉踩内容核查           | 品牌与潜在竞品；默认复用服务 1 回答/引用池；检索渠道和时间窗         | 被拉踩线索、传播来源、事实核查和处置优先级                   |
| 4    | 官网分析   | 官网内容 AI 引用效率分析 | 客户确认的官网；默认复用服务 1 回答/引用池；允许分析的页面范围       | 官网引用率、回答级采纳证据、证据不足结论或内容建议           |
| 5    | 发帖提排名 | 内容发布与排名提升试点   | 目标 Query；事实材料；稿件；媒体范围；预算和授权；服务 1 首轮基线    | 发布 URL 和快照；基于服务 1 两轮指标的试点解释；下一阶段建议 |

服务 2 和服务 3 是两个方向不同、可分别定价的服务。服务 3 只交付疑似竞争性 GEO 线索；没有
作者或投放归属证据时，不把第三方内容直接归因给某个竞品。

## 两个套餐

### 已开展 GEO · 效果评测

执行顺序是 `1 → 2 → 3 → 4`。该套餐适合已经开展 GEO 的公司，用于评测现有排名效果、
双向内容风险和官网内容的 AI 使用效率。

服务 1 使用客户已有 GEO 目标问题。客户确认并冻结测试集后，服务 1 产出回答、排名和
引用池。服务 3 和 4 默认复用该证据集。

### 未开展 GEO · 最小化验证

用户给出的 `13451` 按有序过程实现：

```text
1 基线测试 → 3 找被拉踩帖 → 4 官网分析（条件） → 5 发帖 → 1 同口径复测
```

服务 1 的单位是“轮”，因此此套餐显示 `服务 1 单价 × 2 轮`。复测没有藏在服务 5 的价格
中。官网命中状态未知时，服务 4 作为条件行保留单价，但不进入基础总价，页面和 DOCX 同时
列示命中后的最高总价。明确“已命中”并提供同官网 host 的证据 URL 后，服务 4 进入服务费总价；
选择“未命中”时移除服务 4，执行顺序变为 `1 → 3 → 5 → 1`。

首轮服务 1 之前，我方先提出小规模候选问题，再由客户确认并冻结。首轮服务 1 产出回答、排名、
引用池和基线快照。服务 3、4、5 分别复用这些输出。服务 1 负责两轮采集和指标计算。服务 5 负责
内容发布、发布证据和基于服务 1 结果的试点解释。

套餐只定义服务组合、数量、条件项和执行顺序，不保存或覆盖单价。Operations 页面选择预设套餐后，
只渲染该套餐当前已选服务，未选服务不以禁用卡片占位。自定义组合则始终提供独立的五项服务目录，
由运营人员明确添加或移除服务；下方详情区仍只渲染已选服务，并按目录编号稳定排序。

## 生成输入、服务输入、计价与输出的关系

以下四类信息属于不同阶段，不能混用：

| 模块             | 当前系统如何处理                                                                                                          | 含义                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| 报价生成请求输入 | 页面/API 实际采集客户名、日期、套餐、`artifact_kind`、官网及命中状态、服务单价/数量、价格状态、商务备注、条件性 XLSX/模型 | 用来生成本次指定类型的 DOCX                  |
| 服务执行前输入   | `catalog.py` 为每项服务列出的客户资料清单，渲染进 DOCX                                                                    | 是后续执行前应收集的资料，不代表页面已经收齐 |
| 报价生成器输出   | 指定类型的 DOCX，以及制品类型、套餐、服务数、基础/最高总价、附录计数和 SHA-256 响应头                                     | 是报价制品与传输校验元数据，不是服务执行结果 |
| 服务执行后交付物 | `catalog.py` 为每项服务列出的报告、URL、截图和证据包                                                                      | 只有实际执行并验收后才产生；报价阶段不得伪造 |

```text
客户/官网 + 套餐或自定义服务 + artifact_kind + 价格状态 + 每项单价/数量 + 商务备注
                              │
                              ▼
                    后端校验服务组合和条件
                              │
             ┌────────────────┴────────────────┐
             ▼                                 ▼
     单价 × 数量 = 每项小计       条件性 XLSX → 校验 → Query 规划
             │                                 │
             └────────────────┬────────────────┘
                              ▼
       基础总价 = 非条件服务小计之和
       条件最高总价 = 所有已报价服务小计之和
                              │
                              ▼
                  按 artifact_kind 确定性渲染
          ┌───────────────────┼────────────────────┐
          ▼                   ▼                    ▼
      报价单表格           查询附件            完整报价单
```

金额使用整数“分”保存和计算。浏览器只提交每项单价与数量，不能提交总价。后端重新计算总价，
并通过响应头返回套餐、服务数和总价；浏览器核对它们与本次输入完全一致后才允许下载。

```text
line_subtotal_cents         = unit_price_cents × quantity
total_price_cents           = Σ 非条件 line_subtotal_cents
maximum_total_price_cents   = Σ 所有已报价 line_subtotal_cents
```

除最小验证的官网条件待定状态外，两种总价相等。条件待定时，服务 4 只进入最高总价；调用方不能
手填或覆盖任一总价。

当前版本不提供折扣、税额、代采媒体费或数据库留档。服务 5 是否包含第三方媒体实付费用必须写
入商务备注。任何折扣、税费或代采费用都不能只在备注中参与计算；如需正式支持，应先增加结构化
字段和后端计算规则。

问题数、变体数、渠道、重复次数、URL/页面上限、发文篇数、媒体数、观察窗和验收格式必须在商务备注
或合同中冻结。当前页面尚未把这些范围拆成逐服务结构化字段；它们未确认时，即使单价已填，也只能
生成范围待冻结的报价，不能将其解读为验收工作量已冻结。

## 三种 DOCX 制品

`quotation_config.artifact_kind` 使用固定枚举 `quote_table | query_appendix | complete`。字段缺省时
按 `complete` 处理，以兼容已有调用方。制品类型只决定 DOCX 章节和 Query 规划是否运行，不改变
套餐服务组合、逐项价格或后端总价计算。

| `artifact_kind`  | 页面名称   | XLSX 与 LLM 规则                                                                                                                          | DOCX 输出                                                                                    |
| ---------------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `quote_table`    | 报价单表格 | 不需要 XLSX。Operations 页面隐藏文件输入并清空已选文件；后端不生成 Query 计划，也绝不调用 LLM。直接 API 若仍提交 XLSX，只做安全解析和计数 | 只含报价首页、服务价格表、总价、条件说明和商务条款；不含服务输入/执行/交付附录或任何查询章节 |
| `query_appendix` | 查询附件   | XLSX 必填，且服务组合必须含服务 1 或 5。工作簿解析成功后必须调用允许清单内的研究模型，并得到通过内容契约的 Query 计划                     | 只含与已选 Query 服务对应的查询章节；不含报价表格、总价、商务条款或服务输入/执行/交付说明    |
| `complete`       | 完整报价单 | XLSX 可选。未上传时不调用 LLM；上传且选择服务 1 或 5 时调用 LLM；上传但只选服务 2/3/4 时仅安全解析和计数，不生成 Query 计划               | 始终含报价表格和服务输入/执行/交付说明；只有生成有效 Query 计划时才在其后追加相应查询附件    |

查询章节仍按服务语义裁剪：服务 1 生成原推广 Query 与语义变体；服务 5 生成机会词、优化 Query 与发布相关
章节。`query_appendix` 并不绕过套餐和服务关系校验，价格、数量、官网条件等公共配置仍必须合法。

制品生成遵循以下失败闭合规则：

- 未知 `artifact_kind` 在配置校验阶段拒绝，不能回退成另一种文档。
- `query_appendix` 缺少 XLSX，或组合中同时缺少服务 1 和 5 时，Operations 页面和 API Client
  均禁止请求；服务端仍执行同样校验，不能依赖前端。
- XLSX 不是安全、可解析的工作簿，或不含任何有效目标词时，解析器拒绝；不会生成空查询附件。
- 查询附件需要 LLM 但模型未配置时返回 `503 llm_disabled`；模型执行或内容契约失败时返回
  `502 quotation_generation_failed`；renderer 在没有有效 Query 计划时也拒绝渲染查询附件。
- 浏览器只有在响应 `X-Quotation-Artifact-Kind` 与请求值一致，且 MIME、ZIP 签名、文件大小、
  Query 计数和 SHA-256 等校验全部通过后才下载，不能把错误制品当作成功结果。

## 页面流程

1. 选择“效果评测”“最小化验证”或“自定义组合”。
2. 预设套餐只显示套餐已选服务；自定义组合通过独立的五项服务目录添加或移除服务，下方不展示
   未选服务详情。
3. 填写客户/品牌名称、报价日期和条件性官网 URL。
4. 查看已选服务的客户输入和交付输出，填写单价与数量；修改预设数量会进入自定义组合。
5. 页面实时显示每项小计和总价；价格待确认模式不会虚构金额。
6. 选择“报价单表格”“查询附件”或默认的“完整报价单”，再按制品要求上传 XLSX 并填写商务备注。
7. 生成并下载 DOCX；operator/admin 可生成，reviewer 只读。

报价单表格模式不显示 XLSX 输入。查询附件模式将 XLSX 标为必填；缺文件或已选服务不含服务 1/5
时，页面显示具体错误并禁用生成。完整报价单模式允许不上传 XLSX，此时仍可输出不含查询章节的
报价表格和服务说明。

最小验证套餐提供“待首轮确认 / 已命中 / 未命中”三种状态。待确认时可生成条件报价；服务 4
单独列价且不进入基础总价。已命中时必须填写同官网 host 的引用证据 URL；未命中时移除服务 4。
引用命中由运营人员填写并绑定一条证据 URL，当前页面不会自动导入整批引用池或代替人工确认。

## HTTP API

内部运营接口需要 `project:write` 权限：

```text
POST /api/v2/quotations/generate
Content-Type: multipart/form-data
```

字段：

- `brand_name`：必填，2–80 字符。
- `quotation_config`：必填 JSON 字符串，最大 12,000 字符；其中 `artifact_kind` 为
  `quote_table | query_appendix | complete`，缺省为 `complete`。
- `quote_date`：可选，`YYYY-MM-DD`；缺省为上海时区当日。
- `target_words`：`.xlsx`，最大 10 MiB，最多读取 300 条去重目标词；`query_appendix` 必填，
  `complete` 可选，`quote_table` 调用方应省略。
- `model`：可选；只在制品允许查询章节、上传 XLSX 且选中服务 1 或 5 时使用，并且必须位于允许清单。

效果评测配置示例：

> 下列金额只用于演示整数“分”的接口格式，不是已批准的服务价格。

```json
{
  "package_code": "geo_effect_assessment",
  "artifact_kind": "complete",
  "website_url": "https://www.webray.com.cn",
  "pricing_status": "priced",
  "commercial_note": "验收工作量、税费和付款节点待合同确认。",
  "service_quotes": [
    { "service_code": "ranking_test", "quantity": 1, "unit_price_cents": 2000000 },
    {
      "service_code": "outbound_disparagement_audit",
      "quantity": 1,
      "unit_price_cents": 800000
    },
    {
      "service_code": "inbound_disparagement_audit",
      "quantity": 1,
      "unit_price_cents": 1200000
    },
    { "service_code": "official_site_audit", "quantity": 1, "unit_price_cents": 1000000 }
  ]
}
```

服务端拒绝以下关系错误：重复或乱序服务、套餐服务缺失/多余、最小验证中的服务 1 不是两轮、
自定义服务 5 没有同时购买两轮服务 1、选中服务 4 却没有合法官网、官网证据与套餐/host 不匹配、
已定价服务缺价格、超过安全范围的金额、未知制品类型，以及查询附件缺 XLSX 或缺 Query 服务。

成功响应为 DOCX，包含：

- `Content-Disposition`
- `X-Quotation-Package-Code`
- `X-Quotation-Artifact-Kind`
- `X-Quotation-Service-Count`
- `X-Quotation-Pricing-Status`
- `X-Quotation-Total-Cents`
- `X-Quotation-Maximum-Total-Cents`
- `X-Quotation-Query-Appendix`
- `X-Quotation-Target-Query-Count`
- `X-Quotation-Selected-Query-Count`
- `X-Quotation-Opportunity-Count`
- `X-Quotation-SHA256`
- `Cache-Control: no-store`

未提交 XLSX 时三个 Query 数量均为 `0`，模型不会被调用。允许查询章节的制品上传 XLSX 且选中
服务 1 时生成原词与变体；选中服务 5 时生成机会词、优化 Query 与发布章节。`complete` 只选服务
2/3/4 时，即使直接 API 上传 XLSX，后端也只校验工作簿并记录目标词数，不调用模型；
`query_appendix` 在同样服务组合下直接拒绝。`quote_table` 永不生成 Query 计划或调用模型。

## 命令行

正式效果评测报价：

```bash
.venv/bin/python tools/generate_quotation.py \
  --brand '盛邦安全' \
  --package geo_effect_assessment \
  --website 'https://www.webray.com.cn' \
  --price ranking_test=20000 \
  --price outbound_disparagement_audit=8000 \
  --price inbound_disparagement_audit=12000 \
  --price official_site_audit=10000 \
  --quote-date 2026-08-20
```

价格尚未批准时可加 `--pending-prices` 生成明确标注“待商务确认”的内部样稿。该模式用于版式和
范围核对，不构成正式价格承诺。命令行同样支持
`--artifact-kind complete|quote_table|query_appendix`，缺省为 `complete`。`query_appendix`
必须同时提供 `--target-words`；`quote_table` 不调用模型且不生成查询章节。

## 确定性边界

| 内容                            | 真源                                            |
| ------------------------------- | ----------------------------------------------- |
| 五项服务名称、范围、输入和输出  | 后端 `quotations/catalog.py`                    |
| 套餐步骤、服务 1 两轮、官网条件 | 后端 `quotations/catalog.py`                    |
| 制品类型与章节组合              | 本次 `artifact_kind` + `quotations/renderer.py` |
| 每项单价和数量                  | 本次经过校验的配置                              |
| 小计与总价                      | 后端整数计算                                    |
| 商务条款、版式、页眉页脚        | `quotations/renderer.py`                        |
| 行业画像、代表 Query 和语义变体 | 可选模型输出，经 Pydantic 校验                  |
| 客户原始目标词                  | 上传 XLSX，按 source ID 回绑                    |
| 实测排名、拉踩归因和发帖效果    | 项目执行证据；报价阶段不生成                    |

后端目录是服务端校验与 DOCX 的权威来源，但 Operations 页面和 API Client 当前仍各自维护一份
服务/套餐镜像，用于即时展示和下载前校验。三份定义必须同步更新；后续可增加只读目录接口消除漂移风险。

生成器当前不建立数据库报价记录，也没有报价编号、版本链或商务审批流。SHA-256 用于校验本次 DOCX
字节完整性，不能替代持久化的报价 ID 和审批记录。正式对外出单仍应完成范围、税票、付款和审批确认。

## 执行能力边界

- 服务 1 的报价口径要求独立记录模型开放 API 与豆包 App。API 只是“接口渠道观测基线”，不能等同于无系统提示、无工具或无网关的纯模型能力。当前生产采集注册表主要是消费者网页
  适配器，不能把网页结果改名为手机 App，也不能把网页内部接口请求冒充开放 API 基线。生成报价
  只建立商务范围；执行前仍需接通并验证两类采集通道。
- 服务 2/3 的“找帖”必须在约定 URL、AI 引用链、检索渠道、时间窗和最大条数内执行。当前帖子
  分析入口接收 1–50 个已知 URL，不代表具备无限范围的全网发现能力。
- 服务 4 只对客户确认官网 host 及合法子域做匹配。没有官网 URL 时不能编造采纳率。
- 服务 5 不承诺一定提升。前后矩阵不一致时只能交付描述性结果，不能把变化归因于发帖。
- 正式报告生产链仍沿用旧的四服务编号（旧服务 3=官网、旧服务 4=试点）。当前五服务报价单不会
  自动启动工作流；在执行系统完成语义服务代码迁移前，不应按新编号直接联动正式报告。
