# 客户答案证据页竞品审计与采集端契约建议

日期：2026-08-18

范围：客户工作台“真实 AI 回答”及其上游采集、引用和证据资产
竞品样本：`competitor/aidso`、`competitor/模力指数`

## 1. 结论

客户答案页不能把数据库中的原始响应字符串直接当成阅读界面。

系统应同时保留两种事实形态：

- 采集端保存不可改写的原始响应，供内部审计和解析重放。
- 客户端只直连平台官方分享页，并提供“打开官方原页”和“一键复制分享链接”；不再用我方渲染正文、截图或分享图片代替官方回答。
- 官方分享图和采集现场只保留在内部审计证据域，不进入客户答案页。

平台若通过 `X-Frame-Options` 或 CSP `frame-ancestors` 禁止嵌入，浏览器就会拦截。系统不得绕过平台安全策略，只能清楚说明原因并引导客户打开官方原页。

“有引用”只说明 AI 回答关联了页面。它不自动证明页面提及品牌，也不自动证明回答结论正确。

来源发布时间、来源抓取时间和回答采集时间是三种不同时间。缺少发布时间时必须显示“未知”或“待采集”，不得用抓取时间替代。

## 3. 已落地的答案详情结构

客户点击一条回答后进入“官方回答与引用信源”。

档案顶部展示：

- 原始问题。
- AI 平台、回答模式、地域和精确采集时间。
- 品牌提及、排名、情感、推荐状态和引用数。
- 独立信源数。
- 来源发布时间完整度。
- 官方分享链接的完备状态。

档案只提供两类客户内容：

1. `官方实时回答页`：详情打开后直接在最小权限 sandbox iframe 中请求白名单平台分享 URL，并始终提供新窗口入口和复制链接按钮。
2. `引用信源表`：以 AIDSO 式表格展示序号、站点、站点类型、标题与引用依据、发布时间。

桌面端采用“同题平台目录 / 官方回答 / 引用信源”三栏。手机端先横向切换豆包、DeepSeek、文心一言等同题运行，再用“官方回答 / 引用信源”页签切换，避免长页面滚动。

右侧引用表展示：

- 引用 ordinal、标题、域名和原文链接。
- 自有信源或第三方信源。
- 发布时间及其提取依据。
- AI 返回的引用片段。
- 引用片段哈希。
- 引用与品牌提及、结论真实性之间的边界说明。

本轮已增加 `analytics.citation_fact` 与 `platform.source_document` 的发布时间契约、解析器和投影字段。历史记录或无法可靠提取的来源仍显示“待采集”，且不以回答采集时间、抓取时间或 HTTP `Last-Modified` 冒充发布时间。

## 4. 采集端 P0 契约

### 4.1 answer_run

每次独立采样必须保存：

- `run_id`、`task_id`、`query_id`、重复采样序号。
- 问题原文、问题分类、目标品牌和竞品实体 ID。
- 平台、模型名、可见模型版本。
- 网页端或移动端。
- 快速、深度或其他公开回答模式。
- 联网搜索状态和平台公开展示的思考摘要状态。
- 地区、语言、时区、viewport 和采集通道。
- 计划时间、开始时间、首字时间、回答完成时间和证据完成时间。
- 任务状态、失败阶段、失败原因、重试次数和采集器版本。

不得把平台公开的“思考摘要”命名为模型隐藏推理。

### 4.2 answer_content

每条回答必须分层保存：

- `response_raw`：平台返回的原始事实，仅供内部审计。
- `response_markdown_normalized`：经过平台适配但未改变语义的 Markdown。
- `response_ast`：可重放的结构化节点。
- `response_html_sanitized`：不允许 raw HTML 和危险协议的客户阅读版本。
- `response_plain_text`：搜索、复制和无障碍降级版本。
- `response_hash`：对规范化正文计算的内容哈希。
- `render_parser_version`：渲染器和引用编号转换版本。

引用清单不能再次以“参考来源 + 裸 URL”附加在正文尾部。正文和结构化引用应分别保存并由视图组合。

### 4.3 answer_artifact

每条回答尽可能保存：

- 平台回答 ID、会话 ID 和分享 ID。
- 官方分享 URL、最终 URL、重定向链和白名单校验结果。
- 分享创建时间、过期时间、最近可访问时间和 HTTP 状态。
- 平台是否允许 iframe 嵌入及最近验证结果。
- 官方分享图片、完整长截图和首屏截图。
- 安全 DOM/MHTML 或同源只读归档快照。
- 图片 MIME、宽高、字节数、对象键和 SHA-256。
- DOM 文本、规范化正文、OCR 文本之间的一致性结果。

真实分享图可能达到 `2250×25200`。前端必须缩略展示、限定视口高度并按需加载原图。

上述图片和现场资产仅供内部质检、争议审计和解析重放；客户答案页不得展示。

### 4.4 citation_source

每个来源必须保存：

- 原始 URL、展示 URL、canonical URL、最终 URL和重定向链。
- 页面标题、站点名、域名、发布机构和作者。
- 来源类型、内容格式和语言。
- `published_at_raw`、`published_at`、时区和日期精度。
- `published_at_source` 和 `published_at_confidence`。
- `modified_at`、`fetched_at`、`first_seen_at` 和 `last_verified_at`。
- HTTP 状态、登录墙、反爬、失效和跳转状态。
- 页面正文快照、截图和正文哈希。
- 官网、监管、标准、论文、原始公告、主流媒体、行业媒体或 UGC 等类型依据。
- 原始发布或转载状态，以及重复内容簇 ID。

### 4.5 answer_citation

答案与来源的关系必须独立建模：

- `answer_id`、`source_id` 和平台引用 ordinal。
- 平台原始引用编号制是 0-based 还是 1-based。
- 答案中的字符区间或 DOM/AST 节点路径。
- 被来源支持的准确回答句。
- 来源正文中的支持片段和位置。
- `supports`、`contradicts` 或 `background` 关系。
- 相关性置信度、判定器版本和人工复核状态。
- 首次被该模型引用时间和最近被引用时间。

客户端只有在 ordinal 与来源关系真实存在时才生成可点击引用编号。

## 5. 来源发布时间提取顺序

采集端应保存全部候选值和选择依据。

推荐顺序如下：

1. 页面 JSON-LD 的 `datePublished`。
2. OpenGraph 或文章元数据中的明确发布时间。
3. `time[datetime]` 及语义明确的可见发布时间。
4. 平台引用卡明确展示的发布时间。
5. 页面可见日期文本，并保存上下文和日期精度。
6. URL 日期仅作为低置信度候选。
7. HTTP `Last-Modified` 只能作为更新时间候选，不能默认当发布时间。

冲突时不得静默覆盖。系统应保存候选数组、解析器版本、最终选择和人工修订记录。

建议的置信度状态：

- `verified_structured`：结构化字段与可见时间一致。
- `structured_only`：仅结构化字段可用。
- `visible_only`：仅可见正文时间可用。
- `inferred_low`：仅 URL 或弱上下文推断。
- `unknown`：没有可信发布时间。

## 6. P1 分析能力

答案详情后续应增加：

- 引用完整率：可见引用标记成功映射来源的比例。
- 论断覆盖率：可验证事实中有来源支持的比例。
- 一手来源率：官网、监管、标准、论文和原始公告占比。
- 来源多样性：唯一域名数、来源类型数和集中度。
- 来源新鲜度：最早、最新和中位发布时间，以及未知比例。
- 链接健康度：可访问、跳转、失效和登录墙比例。
- 引用相关性：来源是否支持对应论断，而非只与主题相关。
- GEO 采纳时延：来源发布到首次被模型引用的时间。
- 活动前后差异：回答文本、品牌位置、引用新增或消失、来源时间分布变化。

所有比例必须同时展示分子、分母、观察窗口、样本数和算法版本。

## 7. 保留与验证

- 证据保留期至少覆盖客户合同周期、GEO 基线期、投放期、验证期和争议审计期。
- 不应使用固定 6 个月硬删除作为唯一策略。
- 官方分享链接应定期验证可访问状态，但验证失败不能删除历史分享图或归档快照。
- 页面内容变更时应保存新版本和新哈希，不得覆盖旧版本。
- 每次验证应记录 `verification_event`，包括时间、状态、重定向、内容哈希和失败原因。

## 8. 验收门

采集端达到以下条件后，来源发布时间能力才可从“待采集”改为“已上线”：

- 至少 95% 的可见引用成功映射到规范化来源。
- 发布时间覆盖率按平台和来源类型分别披露。
- 所有时间均带来源、精度、时区和置信度。
- 0-based、1-based、缺号和重复引用均有回归测试。
- 分享链接、分享图和采集截图在契约和界面上严格分型。
- 原始响应仍可内部审计，但客户答案页不展示或复制 Markdown/JSON 源码，只复制平台官方分享链接。
- 页面在桌面、平板和移动端没有横向溢出。
- 超长分享图不会以原尺寸撑开列表或详情页。
