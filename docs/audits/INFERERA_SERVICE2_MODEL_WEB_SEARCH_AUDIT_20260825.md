> 网关：`https://api.inferera.com`

## 一、准入结论

Service 2 的正式模型目录只准入：

| 模型            | 档位          | 输入/输出价格快照（美元/百万 token） | 正式准入原因                                                         |
| --------------- | ------------- | -----------------------------------: | -------------------------------------------------------------------- |
| `gpt-5.6-luna`  | economy，默认 |                            0.2 / 1.2 | 真实 Responses 调用同时观察到供应商搜索事件与 `url_citation`         |
| `claude-opus-5` | premium       |                               5 / 25 | 真实 Anthropic 调用同时观察到 server web-search 事件与供应商工具来源 |

准入策略版本为 `service2-analysis-model-catalog-20260825.2`。策略要求一次独立真实调用同时满足：

1. 网关鉴权成功，模型存在于鉴权模型目录；
2. 响应中存在供应商侧 search/tool/grounding 执行事件；
3. 响应中存在供应商侧 citation/tool result，不能用模型自行生成的 URL 代替；
4. 运行时能逐 item 保存 transport、resolved model、request/response ID、搜索事件数、供应商引用数、token 和安全摘要；
5. 价格和能力作为不可变目录快照写入批次，供应商账单仍是最终费用真相。

## 四、代码约束

- 品牌调研继续使用部署配置的共享模型来源；Service 2 从该来源投影出独立副本，再按本审计白名单收紧。
- 两个业务复用同一 `ModelSelect` 组件，但分别维护选中状态，不发生联动。
- Service 2 批次冻结选中模型的目录 revision、能力、协议、价格和审计策略。
- 每个 corpus item 在调用前持久化唯一 claim；相同幂等身份重放已保存结果，不重复发起可避免的付费请求。
- 运行时没有观察到搜索事件时 fail closed；没有供应商引用时，模型自己输出的 URL 不得成为正式事实核查证据。

## 五、安全处置

会话中曾由操作者提供调用凭据。即使代码与文档没有落盘该值，正式环境继续使用前仍应在供应商侧轮换，并只通过受保护的服务端 secret 注入。轮换不改变上述模型审计结论，但属于发布前安全门禁。
