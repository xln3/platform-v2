# 生产四端口拓扑

当前四个角色暂时部署在 `39.105.175.14`，但从第一天起按可拆到四台机器的网络边界运行：

| 角色 | HTTPS 入口 | 职责 |
| --- | --- | --- |
| 客户页 | `https://39.105.175.14:8787/platform/customer/` | 静态客户应用、浏览器同源 API 边缘代理、答案库 mTLS 读取边缘 |
| 后端 | `https://39.105.175.14:8443/api/v2/` | API、工作流控制面、短信推送入口 |
| OTP 配置页 | `https://39.105.175.14:8080/api/v2/otp/setup` | 无密静态向导及同源 OTP 配置 API 边缘代理 |
| 管理页 | `https://39.105.175.14:8788/platform/operations/` | 运营管理应用及同源 API 边缘代理 |

客户页、配置页和管理页都通过证书固定且要求客户端证书的 mTLS 连接回源
`39.105.175.14:8443`，不使用 `127.0.0.1:8020`，也不关闭上游证书校验。因此后续拆机时只需修改
`deploy/production/geo-platform-v2-frontend-http.conf` 的后端地址，并分别把三个边缘
`server` 块部署到目标机器；浏览器仍使用同源 API，不需要把 cookie 或 token 暴露给
跨域脚本。

答案库与普通浏览器 API 都使用后端 `8443` 的专用 mTLS SNI 虚拟主机；答案正文仍只在
用户进入第四层答案详情时读取，并继续使用更窄的只读 location、限流与禁缓存策略。

OTP 配置页本身可公开打开且不内嵌秘密。`setup-info`、号码注册、状态与验证码查询由
高熵 operator token 和独立限流保护；短信转发手机继续向后端 `8443` 的独立 push
入口发送数据。
