## 1. 系统解决什么问题

每个业务请求先读取本机已经发布的知识。请求再按项目政策选择规则、LLM、网页或其他工具完成当前判断。当前结果不会等待后台治理。任务暴露的未知名称、冲突、过时关系和证据缺口会另行保存为观察。观察经过聚合、补证、审核、历史任务回放和发布门禁后，才能成为所有后续项目可复用的知识版本。

```text
业务请求 → 本机检索 → 规则、LLM 和工具判断 → 返回当前结果
                                          ↓
                    安全观察 → 候选 → 正反证据 → 审核
                                          ↓
                    历史回放 → 不可变版本 → 激活或回滚
                                          ↓
                              SiliconIndex 导入、导出和对账
```

它像 RAG，因为请求会取回外部知识辅助判断。它又不等于传统 RAG，因为它还管理知识怎样根据真实业务反馈改变、结论适用于什么场景、谁批准、更新是否伤害历史任务，以及怎样追溯和回滚。SiliconIndex 是公共知识来源和发布目标，不是生产请求必须在线访问的数据库。

本次实现明确拆开三个问题：文本当前指向哪个对象；当前榜单是否把它汇总到另一个展示对象；它在给定行业、任务、地域、受众和时间下是否具备竞品资格。模型可以按请求政策影响当前结果。一次模型判断只能标记为本次请求推断，不能直接成为跨项目永久事实。

### 七方法工程试验

所有方法使用同一 22 条时间冻结读取模型。基线只看到截止 2026-08-26 23:59:59+08:00 的 `.3` 知识。真实 LLM direct 也从 `.3` 生成修改，没有读取 `.6` 答案。结果如下。

| 方法                                 | 样例正确率 | 跨场景误用 | 实现忠实度                                     |
| ------------------------------------ | ---------: | ---------: | ---------------------------------------------- |
| 不更新知识的传统 RAG 类比            |     0.3182 |          1 | 统一读取模型上的工程类比                       |
| 只追加文档类比                       |     0.3182 |          1 | 统一读取模型上的工程类比                       |
| LLM 直接生成知识修改                 |     0.2273 |          3 | 真实 `gpt-5.6-luna` 修改，再按统一读取模型评测 |
| 专家反馈编辑                         |     1.0000 |          0 | 受控工程类比，不是 STACKFEED 复现              |
| 证据提炼写回                         |     0.8636 |          4 | 受控工程类比，不是 WriteBack-RAG 作者流程复现  |
| 动态新名称解析                       |     1.0000 |          0 | 受控工程类比，不是 DynamicER 训练流程复现      |
| 带适用条件、回放和风险审核的生产实现 |     1.0000 |          0 | 本项目真实实现                                 |

LLM direct 一次运行耗时 39.606 秒，输入 7156 token，输出 4267 token，生成 32 个 patch。供应商没有返回可核验价格，所以成本为 `null`。它的输出哈希为 `sha256:62fa14fc0502c6ac0fa5f3c02b3171baee61428ff30c1b54ca3e9b07f839c967`。

本项目相对不更新和只追加类比的正确率差为 0.6818。10,000 次配对 bootstrap 的 95% 区间为 `[0.5000, 0.8636]`，精确 McNemar 双侧 `p=0.000061`。这个数字不能支持论文优越性声明，因为金标同时用于 `.6` 发布门禁，样本只有 22 条，而且专家、证据写回和 DynamicER 行不是作者流程复现。

研究一得到小样本信号：移除适用条件后正确率从 1.0000 降到 0.8636。研究二得到混合结果：真实项目回放拦住了退化的 `.5`，但在这 22 条样例中移除回放仍为 1.0000。移除反对证据和人工门禁的代理也仍为 1.0000，说明这个小集不能识别它们的独立贡献。研究三尚未在固定人工时长下比较错误发布率和覆盖率。研究四尚未比较完整上下文、脱敏摘要、统计和不可逆引用。当前只能报告工程试验和负结果，不能声称科研创新已经得到证明。

### 保留

- 保留平台现有 FastAPI、PostgreSQL、租户、RBAC、审计和 OpenAPI 基础设施。

- 保留 split SiliconIndex 仓库独有的遮蔽名称、谐音推断和同品类共现代码。
- 保留原始平台工作树和 SiliconIndex 工作树中的所有无关用户修改。本任务没有 reset、stash、覆盖或夹带这些修改。

### 重构

- 通用 `knowledge` Schema 保存观察、候选、证据、提案、裁决、变更集、知识对象、断言、版本、推理记录、缓存和外部同步。
- 通用 `domain/knowledge_evolution` 负责请求记录、观察聚合、审核、版本、发布、回滚、客户端副本和 connector。
- 品牌包只保存品牌对象类型、关系、提示词、证据规则、汇总政策和评测样例。
- 运行时只读取本机不可变知识版本。SiliconIndex 远端只由异步同步器访问。
- 网安公开投影由指定 SiliconIndex 版本确定性生成，不再手工维护第二份 JSON。
- 同步使用“最后共同版本、远端变化、本地变化”三方对账。同字段冲突进入核查，不允许最后写入者覆盖。

### 废弃或拒绝

- `reviewed` 标签不再被当作证据。上一轮 68 个网安实体中 40 个达到公开门槛，28 个降为待核查。186 条名称关系中 145 条发布，41 条待核查。
- `.3`、`.4` 和 `.5` 均未成为公共 SiliconIndex 版本。`.5` 因真实项目回放退化而被拒绝。公共 `.6` 的父版本是最后公共版本 `.2`。
- 单模型高置信、字符串相似和后写入数据都不能直接形成永久归并。

## 4. 请求怎样读取知识、使用 LLM 并保存发现

统一入口是 `POST /api/v2/knowledge/v1/runtime/resolve`。同一契约支持四种策略。

| 策略                 | 行为                                             |
| -------------------- | ------------------------------------------------ |
| `deterministic_only` | 只用已经发布的知识，强调速度和完全复现           |
| `llm_assisted`       | 先查知识，只把歧义或未知项交给模型               |
| `llm_required`       | 每次必须调用模型；失败时按请求明确报错或披露降级 |
| `exploratory`        | 允许发现目录外实体、关系和竞品候选               |

返回结果包含知识版本和哈希、政策版本、模型和模型版本、提示词版本、工具摘要、置信度、知识状态、当前项目是否采用、缓存、token、成本字段、时延和降级原因。模型采用需要模型策略、`allow_external_model=true` 和 `adopt_model_inferred=true` 同时成立。

缓存键包含租户、领域、任务、输入、安全上下文、知识版本和哈希、使用政策、提示词、模型和工具版本。知识或规则升级后不会复用旧判断。严格结构校验会拒绝非法字段、虚构已有 ID、不存在的证据引用和维度矛盾。超时、重试、工具失败、费用上限、模型不可用和隐私限制都有显式错误或降级路径。

生产入口验证了两条不同道路。

- “腾讯云”的 `deterministic_only` 请求使用 `.6`，耗时 2 ms。它解析为业务单元 `CYB-OBJ-TENCENT-CLOUD`，关系为 `business_unit_of`，榜单汇总到 `CYB-BR-TENCENT`。结果状态是已发布知识，没有模型和降级。
- “新大陆数字技术”的 `llm_required` 请求只提供 CTID 和数字身份上下文。系统真实调用 `gpt-5.6-luna` 与 `brand-entity-resolution-v5`。首次耗时 8.775 秒，输入 8786 token，输出 635 token。模型判断现有法人对象 `CYB-OBJ-NEWLAND-DIGITAL` 属于新大陆品牌家族，并只在 CTID、数字身份场景具备比较资格。该结果可以被当前请求采用，但来源仍是 `model_inferred`，没有伪装成发布知识。

远端 SiliconIndex 被阻断时，另一个强制模型请求“新大陆公服公司”仍在 8.117 秒完成。相同请求重试在 9 ms 命中缓存。显式幂等键的首次请求新增一条观察，重试新增零条；数据库最终只有一条对应观察。后台核查没有拖慢已返回的当前结果。

观察只保存任务类型、看到的内容、时间、安全摘要收据、模型或提取器版本和不可逆调用方引用。它不保存客户项目名、完整问题、完整回答或未经控制的客户原文。不同项目的相同名称会聚合到共享候选。

## 5. 新发现怎样成为可回滚知识

系统至少区分四种状态。

| 稳定值                | 中文含义                                     |
| --------------------- | -------------------------------------------- |
| `published`           | 已经进入可供所有业务读取的公共或本机发布版本 |
| `internally_reviewed` | 已经内部审核，但尚未允许公共发布             |
| `model_inferred`      | 只在当前请求中由模型推断，可以按请求政策采用 |
| `unresolved`          | 证据不足或解释冲突，仍无法判断               |

数据模型完整保存一次观察、聚合候选、稳定知识对象、带适用范围的断言、支持或反对证据、审核决定、准备发布的变更集、不可变知识版本、请求推理记录和外部同步记录。证据保存发布者、获取时间、方向、摘要或内容哈希和可信程度。审核保存批准、拒绝、暂缓或重开、所用政策、理由和修改前后内容。

```text
观察 → 聚合候选 → 首选判断和其他解释 → 支持与反对证据
    → 批准、拒绝、暂缓或重开 → 变更集 → 历史请求回放
    → 不可变版本 → 原子激活 → 外部导出和回读对账
```

拒绝或暂缓的候选只有出现新证据、新政策版本或人工重开时才再次进入审核。重要品牌身份、跨层级归并、重要关系和竞品资格不能由单模型直接发布。品牌 release 必须绑定 `historical-replay-v1`、时间截点、评测集哈希、基线和候选错误数、新错误预算与审批。

本机 `.6` 包含 40 个汇总对象。39 个经过证据核验的具体身份保存在这些对象的版本化属性中，包括 29 个法人、4 个集团、3 个业务单元、2 个产品和 1 个机构。每个发布身份都有对象级来源。重复导入同一 `.6` 返回 `already_recorded`，不会增加版本、变更集或激活记录。

## 6. 本机自治和 SiliconIndex 双向同步

本机保存治理过程、数据库对象和不可变业务版本。API、模型、观察、审核、发布和回滚不依赖 Render。客户端短暂无法访问本机服务时，会读取最后验证过的本地副本，并在结果中标明 `client_local_replica`、`knowledge_service_transport_error` 和 `local_replica_deterministic_only`。

SiliconIndex 同步器下载 manifest 和核心集合。它验证 Schema、内容哈希、重复 ID、品牌/名称/关系/分类引用、身份父关系、发布投影和版本倒退。失败只写同步状态，不移动 last-known-good `CURRENT`。
