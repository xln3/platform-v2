# 共享知识更新评测方案与当前证据

## 结论先行

本轮完成了生产发布所需的时间冻结品牌回放、真实项目只读影子回放，以及七种方法在同一个确定性读取模型上的工程类比。后者不是作者训练流程复现：WriteBack-RAG、DynamicER、传统 RAG 和专家编辑行都只是受控 proxy。不能把结果解释成“本项目优于这些论文或专家方法”。当前能证明的是候选版本满足本次工程门禁；研究问题一、二只有小样本先导证据，研究问题三、四尚无结论。

## 数据切分

- `brand_eval_v1.json` 固定 22 条请求，业务时间截点为 `2026-08-26T23:59:59+08:00`。金标分别标注文本身份、对象类型、关系、榜单汇总和场景竞品资格，评测文件有内容哈希。
- 生产影子集包含截点前已经保存的 1309 条合格、非降级答案及其品牌抽取。回放只读数据库，只输出项目不可逆引用、聚合计数和差异，不复制客户原文。
- SiliconIndex `.4/.5/.6`、本机 `.3` 和每次知识 artifact 都是不可修改版本。候选知识晚于请求截点，因此不会把未来知识泄漏到基线输入。
- 22 条金标是本轮人工构造和核验的小型工程集，不是公开 benchmark。1309 条影子集没有逐 mention 人工真值，不能用于计算论文级 accuracy。

## 先导移除实验

| 移除项                | 可重复观察                                                                                                                                                   | 结果与解释                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| 具体 identity object  | 用旧 `.3` 把法人、集团、业务品牌和产品直接折到榜单品牌后，identity/type accuracy 均为 0.541                                                                  | 身份与汇总分开对当前 22 条金标必要；不能外推任意领域                                        |
| 适用条件              | 把 `scope_required` 当 `always`                                                                                                                              | case accuracy 0.8636，4 次错误竞品进入和 4 次跨场景误用                                     |
| 发布前真实历史回放    | `.5` 在原 12 条金标上为零错误，但 1309 条影子回放暴露 121 次新增 unresolved 和目标品牌少 1 次计权；补证后的 `.6` 只保守移除 5 次歧义 `360集团`，目标计数恢复 | 真实回放改变了发布内容；但在 22 条 `.6` 金标 proxy 上移除回放仍为 1.0，是明确的“小集负结果” |

| pending 长名称遮蔽    | 不做遮蔽时，静态解析器会在 pending 的 `360集团` 中命中较短 reviewed 文本 `360`                                                                               | 证明当前解析器需要遮蔽规则；不是语义模型比较                                                |

## 必须报告的指标

研究报告应同时输出：当前任务正确率、实体解析、错合并、漏合并、错误竞品进入、候选发现率、正确发布率、历史退化、发现到生效时间、人工审核分钟数、跨场景误用、来源/版本完整率、p50/p95/p99、模型调用率、缓存率、费用和故障率。没有真实时间戳、人工工时或 provider 费用的组必须写 `not_measured` 和原因，禁止用零代替缺失值。

当前生产性能用 synthetic provider 测编排、校验和缓存；真实 provider smoke 单列。二者不得混合。后续论文实验还需公开或可重复数据、至少三个随机种子、置信区间或显著性检验，并报告强基线更好或没有显著差异的负结果。
