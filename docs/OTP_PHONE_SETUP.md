# 测量手机配置说明（短信自动转发 + 人工接码）

> 目标：把一台 iPhone 或 Android 测量手机配置成 GEO 的验证码转发终端；采集/开户
> 撞到图形验证码时，能在手机上人工接管。

> 设备方案：iPhone 使用苹果自带的「快捷指令」（免费、无第三方账户）；Android 使用
> SmsForwarder APK。SmsForwarder 不能安装在 iPhone 上，但 iOS 的「信息」个人自动化
> 可以把快捷指令输入作为 JSON 变量直接 POST 到同一 GEO 端点。
>
> 配置页是操作员向导：**https://39.105.175.14:8080/api/v2/otp/setup**。页面可经公网
> HTTPS 打开，但静态 HTML 不含任何 token；含密配置、号码注册和状态查询仍须通过
> operator token 鉴权并受独立限流。手机推送使用后端端口 `8443` 的 `/otp/push` 独立入口。
> 本文是该向导的要点与实测坑浓缩；细节冲突时以页面为准。
>
> 需要准备：① 一台能上网的专用测量手机；② 管理密码（operator token，找运维要）。
> 公网入口使用自动续期的公共 CA IP 证书；浏览器或快捷指令一旦出现证书警告必须停止，
> 不得输入 token，也不得把“忽略警告继续”当作操作步骤。

## 0. 先判断你的场景

| 场景                              | 要做的事                                                   |
| --------------------------------- | ---------------------------------------------------------- |
| 新 iPhone + 专用号码              | 走「一、iPhone 免费转发」并完成前台、锁屏两轮验证          |
| 双卡 iPhone                       | 不直接投产；先确认另一线路不会触发，推荐一机一个接码号码   |
| 新手机 + 新号码                   | 第 1～5 步全走                                             |
| 新手机（老号码换机）              | 第 1～5 步全走，备注填老号                                 |
| 老手机 + 新号码                   | 只做第 2 步 + 第 5 步（通道/规则与号码无关，不用动）       |
| 采集/开户撞到图形验证码（滑块等） | 不用提前设置什么——系统会推方糖消息找你，见「二、人工接码」 |

## 一、iPhone 免费转发（Apple 快捷指令）

不安装第三方短信转发器，也不需要订阅。快捷指令直接带 `X-Relay-Token` 调 GEO，
JSON 固定为两个字段：`phone` 是这台测量机的 11 位接码号码，`sms` 是紫色的
「快捷指令输入」变量。

1. 打开配置页，选择 Apple，在顶部输入 operator token 解锁；在「登记接码号码」人工
   核对并注册本机号码。配置页不展示已有号码；管理员可到账号管理页点「刷新号码」核对。
2. iPhone 打开「快捷指令」→「自动化」→「+」→「信息」。按已知平台配置发件人和
   「信息包含」条件；不同发送方分别建自动化，禁止选择全部信息。
3. 选择「立即运行」（旧版界面为关闭「运行前询问」），新建空白自动化。
4. 添加「获取 URL 内容」：方法选 `POST`，URL 复制配置页 iPhone 区域的解锁值。
5. 展开标头，添加 `X-Relay-Token`，Value 复制配置页解锁值。
6. 请求正文选 JSON，添加文本字段：
   - `phone`：刚刚人工核对并注册的 11 位号码；
   - `sms`：从变量选择器插入紫色「快捷指令输入」，不能输入这六个字作为普通文本。
7. 保存后先在亮屏状态接收一条真实格式测试短信，再锁屏重测；两次都要在配置页
   「查看最近推送」看到正确的手机号掩码、平台和码长。

限制与安全边界：

- 信息自动化不能可靠提供双卡中的实际收信线路，因此一台 iPhone 只绑定一个接码号码。
- 自动化保存在本机，不会自动同步到另一台设备；换机后必须重做并复验。
- 只能用于专用测量号码。不要把触发条件泛化为所有短信或所有验证码。
- 「获取 URL 内容」不应出现证书警告。出现时说明公共 CA 证书续期或入口配置异常，
  应停止配置并联系运维；不得改成 HTTP 或关闭证书校验。

## 二、Android 短信自动转发（SmsForwarder）

配置页顶部先切换到 Android，再逐步执行；下面只标每步要点和实测踩过的坑。

1. **第 0 步 · 防杀（最容易翻车，务必逐条做）**
   - 系统设置 → 应用管理 → SmsForwarder：省电策略 = 无限制、开自启动、最近任务卡片下拉锁定；短信/通知权限授予。
   - **SmsForwarder → 通用设置 → 免打扰(禁用转发)时间段 = `00:00 ~ 00:00`**。起止相等 = 该功能停用；20260810 实测被设成 `00:00 ~ 24:00`（= 全天禁转发），一条都发不出。
2. **第 1 步 · 安装**：页面先校验制品清单，再开放 APK（v3.5.0.260224，服务器自托管）
   下载；页面显示 SHA-256 和签名证书指纹，校验失败时按钮保持禁用。哈希一致只证明拿到
   既定文件：当前审查的第三方客户端仍会绕过 HTTPS 证书错误，受控 pin 客户端上线前
   只能在管理 VPN 等隔离链路中临时使用。已装过可跳过。
3. **第 2 步 · 卡槽备注 + 号码入册**：
   - SmsForwarder → 通用设置 → 个性设置 →「SIM1主键/备注」「SIM2主键/备注」的备注框，填**含该卡真实号码**的文本（App 提示格式 `运营商_手机号`，如 `中国移动_18810936058`）。服务端靠号码反解归属，不靠机身标识。
   - 新号码先在页面「注册新号码」入册（需先解锁）：填 11 位号码，卡槽/运营商选填；
     注册成功后再点明确的「复制」按钮，粘贴进上面对应 SIM 的备注框。配置页不会列出
     已有号码；管理员到账号管理页点「刷新号码」后，可用完整号码核对同步结果。
4. **第 3 步 · 发送通道（Webhook）**：照页面逐格复制/选择（Webhook Server、消息模板、Headers 的 token 值解锁后显示）。两个实测坑：
   - **消息模板必须与复制值逐字符一致**——多一个 `"` 服务端就归不了号（码不丢，但落 unrouted，查码按号查不到）。
   - v3.5.0 没有「忽略 SSL 证书」UI 开关，但现有二进制仍会绕过证书错误；没有开关不
     等于已恢复服务器身份校验。受控 pin 客户端或 VPN 隔离完成前不能把链路标记为安全。
5. **第 4 步 · 转发规则**：照页面逐格。规则要求“明确平台签名 + 验证码业务词”同时
   命中，不再以“百度”“腾讯”等泛品牌名独立放行。它仍需持续用支付、密码重置、社交
   私信等负向样本复核，不能作“任何隐私短信绝不会离开本机”的绝对承诺。建议只使用
   专用测量号码，切勿把规则泛化成“所有验证码”。
6. **第 5 步 · 验证**：用另一台手机给测量号发一条形如「【豆包】验证码 123456」的短信；
   页面点「查看最近推送」能看到它（手机号掩码 + 码长 + 平台）= 全链路通。通道页的
   【测试】按钮只能自检发送通道，不能替代白名单规则验证。

## 三、人工接码（图形验证码人工接管，方糖推送）

**是什么**：采集或开户途中撞到图形验证码（拖滑块、点选文字等）时，系统会**自动挂起任务**，同时通过**方糖**（Server酱·Turbo）把一条接管链接推到运维的微信——不用人盯系统，收到推送再动手，全程约 30 秒。

**首次使用，先配一次推送（收码的人做一遍即可）**：

1. 微信关注「Server酱·Turbo」公众号（方糖），按号内指引拿到自己的 SendKey。
2. 把 SendKey 发给运维，由运维配进服务器推送通道（约 1 分钟）。
3. 已经能收到推送的手机，跳过本步。

**收到推送后**：

1. 微信里点开方糖消息 → 点里面的接管链接。
2. 手机页面显示服务器上平台页面的**实时画面**——照画面把图形验证做完（拖滑块/点选），只动验证码本身，页面上其他按钮、链接都不要点。
3. 点页面底部「**我已完成，继续采集**」→ 显示「已解决，采集已自动恢复」即结束：系统自动断点续跑，不用再做任何操作。

**注意**：

- 接管链接一次性、有时效（约 1 小时），收到请尽快处理；同一任务最多接管 3 次，都超时则任务按失败计。
- 开户类接管（运维手动发起的会话）页面上的完成按钮无效——运维说一声「好了」才算完。
- 收不到方糖推送：找运维确认 SendKey 是否已配上。

## 四、速查与排障

| 症状                                  | 原因（实测案例）                       | 处置                                                                                |
| ------------------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------- |
| iPhone 自动化完全不触发               | 未选立即运行/仍在运行前询问            | 修改自动化运行方式后锁屏重测                                                        |
| iPhone 到达但系统查不到码             | `sms` 填成普通文字或 `phone` 填错      | 改为紫色快捷指令输入变量，并在账号管理页核对完整号码                                |
| iPhone「获取 URL 内容」报证书错误     | 公共 CA 证书续期或入口配置异常         | 停止配置并联系运维，禁止绕过证书校验                                                |
| 全天零推送                            | 全局免打扰 ≠ 00:00~00:00（20260810）   | 通用设置改回 `00:00 ~ 00:00`                                                        |
| 推送到达但系统查不到码                | 消息模板被改坏（多一个引号，20260810） | 与页面复制值逐字符对齐                                                              |
| 时而收不到、重启 App 就好             | 国产 ROM 杀后台（20260807）            | 重做第 0 步防杀                                                                     |
| 页面复制的 Webhook 地址没有 8443 端口 | 反代丢端口，已修复（20260810）         | 刷新页面重新复制                                                                    |
| 找不到「忽略 SSL 证书」开关           | v3.5.0 无 UI 开关，但二进制仍绕过校验  | 不靠 UI 判断安全；按过渡期 VPN/受控 pin 客户端方案执行                              |
| 配置页返回 404/无法连接               | 误用了后端端口或配置页监听未部署       | 使用 `https://39.105.175.14:8080/api/v2/otp/setup`，并检查 Nginx 的 8080 HTTPS 监听 |
| APK 下载按钮不可用                    | 文件缺失或 SHA-256 清单校验失败        | 按页面 request ID 查日志并核对制品清单，禁止绕过校验直接分发                        |
| 收不到方糖接管推送                    | SendKey 未配/推送通道未配              | 找运维确认配置                                                                      |

运维需要的服务端细节（端点、token、工具用法）不在本文——见 `api/geo_platform/otp/router.py` 与 `tools/otp_assist_login.py` 的 docstring。
