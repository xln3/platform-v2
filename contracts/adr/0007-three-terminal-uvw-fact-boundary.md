# ADR-0007: 三端边界与 UVW 权威事实

Status: Accepted · 2026-08-21

Owner: GEO Platform

## Context

客户门户、后端事实源和管理应用当前可以同机部署，未来需要能分别部署。历史采集主要保存最终引用，无法把检索候选、实际打开页面和答案采用片段区分开；旧页面体检还把一次处理批量误写成业务全集上限。客户和内部接口也不能继续只靠前端隐藏字段来区分安全边界。

本决定补充 ADR-0001，不改变 FastAPI 模块化后端、PostgreSQL/CAS 和 Temporal worker 的既有职责。

## Decision

1. 采用一个逻辑后端事实源、两个独立前端安全域。三个主要部署角色是客户门户与客户同源边缘、后端事实源、管理应用与管理同源边缘。Operations、Intelligence 和 Report Studio 属于同一管理安全域；OTP 等辅助入口不另建业务事实源。
2. 前端只能通过 API 访问后端。API、客户页和管理页地址使用部署配置；任何前端不得读取后端本地文件、数据库或 CAS object key。
3. 本轮先拆分响应 DTO、接口职责和权限。内部信源目录要求 `intelligence:*` 权限；客户接口使用白名单投影和 DLP。当前 Cookie、OIDC audience、mTLS 客户端证书、Nginx 白名单和同浏览器跨应用跳转保持兼容，不做强制拆分。
4. UVW 使用唯一语义：U 是平台实际返回且可观察的全部 URL 候选 occurrence；V 是其中被平台实际打开/读取的子集；W 是可逐字或以其他明确依据绑定到页面版本和答案的内容片段。不可观察状态保持 `unobserved`，不反推为 0。
5. URL 和站点可以形成规范身份；每一次问答、检索词、轮次和平台发生记录不可去重删除。旧最终引用只回填其能证明的阶段，U/V/W 标记为历史不可观察。
6. 回答、现场证据、检索事件、U/V occurrence、完成事件和只引用该回答的下游任务在同一采集事务提交。公开页抓取、W、页面体检、风险、官网和报告分析在独立 worker 中执行，失败不能回写采集失败。
7. 所有 U 进入公开页处理分母。分页、分批、背压、超时、响应尺寸和重试可以控制节奏，不能用 Top-N 或总量上限缩小业务全集。
8. W 和页面 finding 共用“来源正文逐字子串 + 字符区间 + 哈希 + 页面版本”校验契约。已检查独立 `persona-scan` 工作树：其 occurrence 消歧和规范化文本到原文区间回映射与该契约一致。由于它是独立部署且当前有未提交演进，本轮不复制或覆盖其实现，也不建立跨工作树运行时导入；平台 W 复用既有 `validate_exact_interval`。后续抽取共享包时必须保留相同失败关闭契约。
9. W 的正结果与 `no_evidence` 负结果都保存 occurrence、页面快照、输入哈希和策略版本；缺少版本化分析行表示未知，不能把 chunk 表的缺行解释成零。人工复核以追加式决定事实保存，要求 `intelligence:review` 和幂等键；chunk 与 occurrence 上的复核/W 状态只是可重建当前投影，不能覆盖分析或复核历史。程序逐字校验已拒绝的 span 不能由人工复核改成有效 W。服务 5 的建议来自两个版本化观察对照：V 对 U−V、高 W 对低 W。它们只生成待验证假设；最终效果仍使用服务 1 的同题、同平台、同地域、同重复次数前后测，时间先后不解释成因果。

## Consequences

- PostgreSQL 新增规范站点/URL、检索事件、occurrence、抓取尝试、页面快照、W 分析版本、片段与人工复核、内容策略分析和五服务授权事实；它们仍属于同一权威事实源。聚合和前端 DTO 是可重建投影。
- 管理侧可以按项目→站点→URL→occurrence→回答双向钻取；客户只能看到已授权服务投影。
- 迁移先建表、索引、RLS 和角色授权，再回填历史最终引用。降级会删除新投影表和关联列，因此生产降级前必须先导出新 UVW 事实；旧回答和旧报告表不被改写。
- 本 ADR 不代表生产三机拆分已完成，也不授权证书、登录会话、反向代理或真实平台账号变更。
